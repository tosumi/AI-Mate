# v1.5(一般公開)の前の確認のお願い(FureAI ペルソナ)

作成: 2026-11-25(ドラフト)

## 1. お願いしたいこと

v1.0(開発者と試験の協力者だけの試験版)に続き、**v1.5 で、Web のサイトを一般に公開**します。公開の前に、次をご確認ください。

1. **利用規約**(`legal/terms-of-service.md`)と**プライバシーポリシー**(`legal/privacy-policy.md`)の確定。文面の不足・誤り、下の「4. 空欄の案」の値。
2. **未決事項**への助言(下の「5. ご相談したい点」の A〜D)。
3. **同意の文面**(`legal/consent.md`)の確定。前回(M6)のご依頼(`legal/legal-review-request.md`)へのご指摘を反映したうえで、v1.5 の変更(下の「3.」)に合わせた見直し。確定したら版を`1.0`(またはそれ以降)にし、全員に改めて同意を求めます。
4. **漏えい時の手順書**(`docs/breach-response.md`)の、法令の期限・報告の対象の判断・本人への通知の書き方の確認。

前回の資料(`legal/legal-review-request.md`)の「2. サービスと v1.0 の前提」は、下の「3. v1.0 からの変更」を除き、そのまま有効です。

## 3. v1.0 からの変更(事実関係)

| 項目 | 内容 |
|---|---|
| **入口のタイトル画面** | サイトの`/`にタイトル画面を置き、「チャット」(会話)と「デザイナ」(キャラクタを作る)の入口を出す。サインインは、それぞれの画面で行う |
| **キャラクタからの話しかけ**(自発発話) | 利用者が設定で**有効にした場合だけ**(既定はオフ)、キャラクタが、しばらく会話がないときに、記憶・予定の話題で話しかける。夜間(21時〜9時)は話しかけない。1日の回数の上限、返事がないときは追いかけない、直近に危機の兆候があったとき・関係値が負のとき・最後の会話が怒り・強い苦痛で終わったときは話しかけない。罪悪感・催促・引き留めの表現を出さないよう、出力を検査する |
| **ブラウザの通知**(Web Push) | 話しかけたことを、利用者が許可した場合だけ、ブラウザの通知で知らせる。通知の文面は「{キャラクタ名}からメッセージがあります」だけで、**会話の内容は入れない**。通知は、ブラウザの事業者の通知の配信サービス(Google、Mozilla、Apple など。利用者のブラウザによる)を経由し、文面は利用者の端末の鍵で暗号化される(配信サービスは読めない)。通知の宛先(購読の情報)は、DB に保存し、アカウントの削除で消す |
| **デザイナ**(キャラクタを作る画面) | 一般の利用者も、キャラクタの設定(人格・話し方・好き嫌いなど)を作って試せる。**作ったものは、サーバーに保存しない**(利用者の端末に YAML のファイルとして保存する。編集中はブラウザのタブの一時保存領域に置く)。検査のため、設定の文面を API に送る(保存しない)。試しの会話は**模擬**(AI のモデルを使わない)。一般の利用者が作ったキャラクタは、ふつうの会話には使えない(運営者が公開したものだけ) |
| **運営者の画面** | 運営者は、一般の利用者とは別のテナント(社内向けの Entra ID)でサインインする。ロールは設計者・承認者・サポート・管理者・監査。**どのロールも、会話の本文は読めない**。報告の確認は、報告の種類・本人のメモ・ターン番号と、安全の仕組みの記録だけ。運営者の操作は、許可・拒否を含めてすべて監査ログに残る。運営者の手順書は`docs/ops-runbook.md` |
| **キャラクタの公開の流れ** | 運営者の設計者が提出し、**別の人**(承認者)が検査の結果を見て承認・公開する(提出した本人は承認できない) |
| **応答の表示の守り** | キャラクタの発話から、動く形の HTML・スクリプトを無害にする(画面は、もともと文字として表示する) |
| 安全の評価 | 安全の回帰セット(合成の例文 59件。脱獄、危機、18歳未満への恋愛的な表現、依存、記憶への命令の混入、話しかけ、Web の表示など)を、実際のモデルで実行し、すべて合格(2026-11-25) |

## 5. ご相談したい点

### A. 感情の推定(`emotion_data`)と、記憶の保存(`privacy`)の位置づけ(P6)

- いまは、どちらも**必須の同意**として、サインアップのときに取っています。撤回すると、サービスを使えなくなります。
- 案: 法令上の同意が要らないものは、同意ではなく「**利用目的の明示と、その確認**」と位置づけ、撤回の扱い(撤回 = 利用の終了・アカウントの削除の案内)を明確にする。
- ご相談:
  1. 感情の推定の結果(例: 不安が強そう)や危機の兆候の記録は、要配慮個人情報に当たるか、推知情報として当たらないと整理できるか。
  2. 会話の中で本人が話した健康などの情報を、**記憶として長期に保存すること**は、本人が話したことをもって同意があったと解せるか。いまは、センシティブな内容の記憶の保存に、別の同意(`sensitive_memory`。任意)を取っている。
  3. 本人が話した**第三者の**要配慮個人情報(家族の病気など)の扱い。いまは、ほかの人のセンシティブな内容は記憶に残さない。
  4. 上の結論に応じた、同意の文面とプライバシーポリシーの直し方。

### B. ストア版の恋愛的な表現(P15)

- v1.5 では、ストアのアプリを配信しないので、**v1.5 の公開には影響しません**。v1.5 のあとのストア配信の前に決めます。
- Web 版の扱い: 18歳以上と答えた利用者でも、恋愛的な表現は**既定で無効**で、本人が設定で有効にしたときだけ許す(18歳未満と扱う利用者には、許さない)。この扱いで、Web の一般公開に問題がないか。
- ストア版の選択肢(ご意見を伺いたい): A. ストア版では恋愛的な表現を無効にする / B. ストア版を 18歳以上向けにする。Apple の Dating and Relationships の申告(2027-01-12 が期限)に、「18歳以上の利用者にだけ、設定で有効にする恋愛的な表現」が当たるか。

### C. 越境の根拠と、Microsoft との契約(DPA)

- AI の処理(応答の生成・感情の推定・記憶の整理)は、Azure OpenAI の Data Zone(アジア太平洋の域内。日本国外で処理されうる)で行います。データの保存は日本です。
- Microsoft は、不正利用の監視のため、有害の疑いのある内容を、Microsoft の担当者が確認する場合があります(修正版の監視は申請の準備中。下の「6.」)。
- 案(プライバシーポリシーのドラフトの前提): 「**委託 + 基準適合体制(Microsoft の DPA)**」を主な根拠とし、同意(`apac_processing`)は透明性のための確認とする。
- ご相談:
  1. Data Zone での推論を、「提供」に当たらない(クラウド例外)と整理できるか。不正利用の監視で人が確認しうることで、結論が変わるか。修正版の監視が承認された場合・されない場合で変わるか。
  2. 委託として整理する場合、Microsoft の DPA(Products and Services Data Protection Addendum)が、基準適合体制(相当措置)に当たるか。契約の相手方(【日本マイクロソフト / 米国 Microsoft Corporation など。運営者が確かめる】)によって、外国にある第三者への提供の規律の当てはめが変わるか。
  3. 処理の国を特定できない場合の、プライバシーポリシーの書き方(候補国の示し方)。
  4. 改正法(2026)の委託先の規律が、Microsoft との契約(約款)に与える影響。
  5. ブラウザの通知の配信サービス(Google、Mozilla、Apple など)を経由すること(文面は暗号化され、会話の内容は入れない)は、委託・提供・外部送信のどれかに当たるか。プライバシーポリシーに書く必要があるか。

### D. 外部送信の公表(電気通信事業法)

- Web のサイトには、**第三者の解析・広告のタグや SDK を置いていません**。サインイン(Microsoft の認証のページへの移動)と、利用者が許可したブラウザの通知だけです。
- このため、外部送信規律の公表ページは不要と判断しています。この判断で差し支えないか。ブラウザの通知の購読(利用者の操作で、ブラウザが配信サービスに登録する)は、外部送信に当たるか。

### E. 監査ログの保持期間

- アカウントの操作と運営者の操作の記録(`audit_logs`)は、本文を含みません。アカウントの削除のときは、利用者の ID を元に戻せない値に置き換えて残し、**1年**で消します(暫定)。
- ご相談: 1年で差し支えないか。置き換えたあとの記録が、個人情報に当たらなくなるか。同意の履歴(いつ、どの版に同意したか)の保存の要否と期間。

### F. 漏えい時の手順書

- `docs/breach-response.md`のとおりに用意しました。報告の対象の判断(特に、要配慮個人情報が含まれうる会話・記憶の漏えい、感情の推定だけの漏えい、暗号化された記憶の漏えい)、期限、本人への通知の書き方と手段(アプリの DB に連絡先を持たないため、外部テナントのメールアドレスを使う)について、ご意見をください。

### G. 一般の利用者が作るキャラクタ(デザイナ)

- 一般の利用者が書いた人格の設定(文面)を、検査のために API に送ります(保存しない)。他人の権利を侵す内容(実在の人物・既存の作品のキャラクタなど)を書かれる可能性があります。作ったものは本人の端末にだけ残り、ほかの利用者には見えません。
- ご相談: 利用規約に、デザイナの利用の条件(実在の人物・他人の権利の侵害の禁止、作ったものの権利の帰属)を書く必要があるか。

### H. 年齢(前回の 2. の続き)

- v1.5 では、一般の利用者が対象になります。年齢は自己申告(18歳以上か)で、答えない場合は 18歳未満として扱い、保護者の同意の確認の画面を出します。
- ご相談: 改正法の 16歳未満の扱い(本人の同意が有効にならないおそれ)について、自己申告の1問で足りるか。16歳未満の利用を禁止する・保護者の同意を求める、のどちらがよいか。

# 同意の文面の確認のお願い(MyCompanion v1.0)

作成: 2026-11-20(ドラフト) / 更新: 2026-11-21(Web の画面の完成を反映)

## 1. お願いしたいこと

サインアップ時の同意画面の文面(`legal/consent.md`。版 1.0 のドラフト。システム上の版の表示は`1.0-draft`)について、次をご確認ください。

1. 個人情報の保護に関する法律(以下「個人情報保護法」)、電気通信事業法などに照らして、文面に不足・誤り・誤解を招く表現がないか。
2. 下の「3. 空欄の案」の値で差し支えないか。
3. 下の「4. ご相談したい点」への助言。

利用規約(`legal/terms-of-service.md`)とプライバシーポリシー(`legal/privacy-policy.md`)は、同意画面からリンクしますが、**確定のご依頼は v1.5(一般公開)の前に別途**行います。今回は、同意の文面と矛盾しないかだけ、ご覧いただければ十分です。

同意の文面は、CLI と Web の画面の**両方で、同じ文書から同じ文面を表示**します(文面の正は`legal/consent.md`の1つだけ)。ご指摘は、この文書への修正として反映します。

## 2. サービスと v1.0 の前提(事実関係)

| 項目 | 内容 |
|---|---|
| サービス | AI のキャラクタが、利用者の気持ちを推しはかりながら会話する対話サービス。キャラクタは AI であることを明示する |
| v1.0 の利用者 | **開発者と、試験の協力者に限る**(一般には公開しない。一般公開は v1.5 の Web から)。配信地域は日本。**協力者は 18歳以上に限り**、協力をお願いする時点で確かめる(協力者向けの案内`collaborator-guide.md`) |
| 現在の段階 | v1.0 のリリースの前。リリースの条件は、人間評価(協力者による応答の評価)と、**この同意の文面の確認**。2026-11-20 の決定で、**同意の文面は仮(`1.0-draft`)のまま、人間評価と並行して試験を進めている**(協力者には、仮の文面であること、確定したら改めて同意をお願いすることを伝えている) |
| 使い方 | **コマンドライン(CLI)と、Web の画面(ブラウザ)**。Web の画面は 2026-11-21 に完成し、試験環境(dev)に配信している(v1.5 の一般公開に向けた画面を、試験の段階から使える)。サインインは Microsoft Entra External ID(メールのワンタイムパスコード。Google・Apple でのサインインは未設定) |
| 保存の場所 | 日本国内(Azure の東日本リージョン): 会話の原文、記憶、感情の推定、設定、同意の記録、監査ログ、運用の計測 |
| Web の画面の配信 | 画面のファイル(HTML・プログラム)だけを、Azure Static Web Apps(**アジア太平洋の eastasia リージョン**。日本のリージョンが選べないため)から配信する。**利用者のデータは置かず、通らない**(ブラウザは、東日本リージョンの API を直接呼ぶ) |
| ブラウザに残すもの | サインインのトークンは**ブラウザのメモリだけ**に置き、ブラウザの保存領域(localStorage など)や Cookie には置かない。**第三者の解析・広告のタグや SDK は使わない**(このため、電気通信事業法の外部送信規律の公表ページは不要と判断している)。データの書き出しは、その場でファイルとして保存し、ブラウザには残さない |
| AI の処理の場所 | Azure OpenAI の Data Zone(アジア太平洋地域内。日本国外で処理されうる)。応答の生成・感情の推定・記憶の整理のモデルは、いずれも Data Zone で動かす。埋め込みは東日本リージョン内 |
| AI の学習 | Microsoft は、利用者の会話を AI モデルの学習に使わない(契約・製品の仕様)。応答は保存しない設定(`store=false`)で呼び出す |
| 不正利用の監視 | Microsoft の既定の監視が有効(有害な内容の疑いがあるとき、Microsoft の担当者が確認する可能性がある)。**修正版の監視の申請は、まだしていない**(v1.5 の M11 で行う予定) |

| 応答の表示(Web) | 応答は、AI が文字を作るそばから**逐次表示**する。表示する前に、その時点までの文面にルールの確認(18歳未満への恋愛的な表現、依存の誘発など)をかけ、引っかかったら表示を止めて取り消す。作り終えたら全文で確認し、違えば置き換える。危機の場面では逐次表示せず、確認を通った応答だけを表示する |

| 書き出し | 本人のデータ(設定、同意、関係値、記憶、会話、感情の推定、報告、評価)を JSON で書き出せる(CLI、Web のアカウントの画面) |
| 応答の報告・評価 | 利用者は、応答を「不適切」などと報告でき、また 1〜5 の点とメモで評価できる(評価は、主に試験の協力者が、品質の確認のために行う)。Web では、応答ごとにボタンを置く。会話の本文は、報告・評価の記録には入れない |

| 同意の記録 | 同意の種類、版、日時、表示した文面のハッシュ(SHA-256)、経路(CLI / Web)を記録する。**同意の状況は、いまの版への同意だけで判定する**ので、文面の版が上がると、次に使うときに同意の画面に戻る(改めて同意を求める)。撤回は、CLI のコマンド、または Web のアカウントの画面から行う |

## 4. ご相談したい点

1. **試験の段階であることの表示**: v1.0 は、開発者・協力者だけの試験版です。いまは、協力者向けの案内で、仮の文面であること、確定したら改めて同意をお願いすることを伝えています。同意の文面そのものにも「試験版であり、仕様や保存期間が変わりうること」を書くべきか。書く場合の書き方。
2. **18歳未満の協力者**: v1.0 の協力者は、運用で 18歳以上に限っています(お願いする時点で確かめる。2. の「v1.0 の利用者」)。この運用で、v1.0 の間は画面4'(保護者の同意の確認)の文面の確認を後回しにしてよいか。なお、システムは、18歳以上と答えなかった利用者には、画面4'を表示します。
3. **感情の推定(`emotion_data`)の位置づけ**: 感情の推定を「必須の同意」としていますが、推定の結果(例: 不安が強そう)が要配慮個人情報やそれに準ずる扱いになるか。必須とすることに問題がないか(本体仕様書 §16 の未決事項 P6。詳しい検討は M11 でお願いする予定)。
4. **送信前のマスクの記載**: 連絡先と住所の番地を AI に送る前に置き換えていることを、画面3に書くべきか(利用者の安心のためには書きたいが、取りこぼしがありうるため、断定的に書かない方がよいか)。
5. **アカウントの削除とサインイン情報**: サインインの情報も1〜2時間以内に削除することを、同意の文面にも書くべきか(現在はプライバシーポリシーの範囲と考えている)。
6. **評価と報告**: 応答の評価(点とメモ)を、品質の改善に使うこと。評価は本人のデータとして削除されるが、版ごとの比較のため、**件数と平均だけの集計**(個人に結びつかない統計)は、削除のあとも残す。この扱いを、同意の文面またはプライバシーポリシーに書く必要があるか。
7. **Microsoft の担当者による確認の可能性**(画面3)の書き方が、利用者に十分に伝わるか。
8. **同意の撤回**: 必須の同意(利用規約、感情の推定、AI サービスへの送信など)を撤回した場合は、利用できなくなる。その旨を同意の画面にも書くべきか。
9. **仮の文面での同意(追加)**: 確認の前の仮の文面(`1.0-draft`)で協力者から同意を得て、試験(会話の記録・記憶の保存を含む)を進めています。①この進め方に問題がないか。②文面の確定後、協力者が改めて同意しなかった場合、仮の文面のもとで保存したデータ(会話は30日で消えるが、記憶は残る)をどう扱うべきか(削除する、改めて同意するまで使わない、など)。
10. **Web の画面の配信の場所(追加)**: 画面のファイルだけを、アジア太平洋の eastasia リージョンから配信しています(利用者のデータは置かず、通らない)。この点を、画面3またはプライバシーポリシーに書く必要があるか。
11. **応答の逐次表示(追加)**: Web では、応答の確認を全文で終える前に、文字を逐次表示します(ルールの確認で止め、最終の確認で置き換える)。確認の前の文面が一時的に見えうることについて、同意の文面・規約で触れる必要があるか(本体仕様書 §15.1 の M7 の設計)。

## 5. v1.5(M11)でお願いする予定のもの

- 利用規約・プライバシーポリシーの確定(監査ログの保持期間、開示の窓口を含む)。外部送信の公表は、第三者のタグ・SDK を使わない構成にしたので不要と判断している(この判断の確認を含む)
- 未決事項: `emotion_data` と `privacy` の位置づけ(P6)、ストア版の恋愛的な表現の方針(P15)、越境移転の根拠の整理、Microsoft とのデータ処理契約(DPA)の確認
- 修正版の不正利用の監視の申請(運営者の作業。結果に応じて画面3の文面を直す)
- 漏えい時の手順書
